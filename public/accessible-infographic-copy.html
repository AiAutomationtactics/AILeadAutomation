Write Accessible Infographic Copy That Works Without the Image

An infographic should make a lesson easier to grasp, not make the information unavailable to readers who cannot see it. Write the explanation first, then design the image.

Home / Write Accessible Infographic Copy That Works Without the Image
In brief: An infographic should make a lesson easier to grasp, not make the information unavailable to readers who cannot see it. Write the explanation first, then design the image.

Decide what the image is supposed to teach

Before opening a design tool, complete this sentence: “After reading this, someone should be able to ___.” A useful answer is “separate website visits from confirmed newsletter signups.” “Feel excited about growth” is not an instructional outcome. An infographic can illustrate a process, compare options, or summarize a small set of facts. It cannot replace a missing explanation of how to act on those facts.

Choose one format that fits the relationship: a sequence for ordered steps, a comparison for tradeoffs, or a labeled diagram for components. Do not use a chart merely because a chart looks authoritative. If your numbers are invented for teaching, mark them illustrative both in the image and in the surrounding text.

Worked example: a three-step traffic measurement diagram

Suppose a beginner asks, “Why do I have clicks but no subscribers?” Create a diagram with three boxes: 1. Tagged link clicked → 2. Landing page visited → 3. Signup confirmed. Under each box, add a plain-language definition. A click reported by a social platform is not automatically a successfully loaded visit, and a submitted form is not necessarily a confirmed subscription. Each step uses a different measurement source.

The accompanying article should say the same thing in ordinary text: “First, label your campaign link so you can identify its source. Second, check whether visitors reached the page in your analytics. Third, verify the signup in your email service. Compare these as separate measures; investigate discrepancies rather than forcing the totals to match.” This paragraph is useful even if the diagram fails to load.

Choose between alt text and a longer text equivalent

Alt text is a concise alternative that communicates the image's purpose in context. For the simple three-box diagram, try: “Three-step diagram: campaign link click, landing-page visit, then confirmed email signup; each is a different metric.” That is more helpful than “traffic SEO marketing infographic” or “image123.”

A dense infographic containing detailed definitions, exceptions, or several comparisons may need a full text equivalent in the page body. Do not cram every label into an enormous alt attribute. Introduce the image, describe the meaningful relationships nearby, and provide a structured explanation or data table if the information requires one. When a decorative flourish contributes no information, use an empty alt attribute rather than repeating surrounding text.

The W3C Web Accessibility Initiative's image accessibility tutorial explains how an image's purpose and context affect the appropriate text alternative. The same image may need different wording on different pages.

Make the visible copy legible on a phone

Write a short, descriptive heading and one clear label per step. Prefer familiar words: “Confirmed signups” is clearer than “conversion events” for an introductory lesson. Avoid placing paragraphs inside a narrow graphic. A phone preview can reveal labels that looked comfortable on a desktop canvas but became unreadable after resizing.

Check contrast between foreground text and its background, including text over gradients or photographs. Never rely on color alone to distinguish “good” and “bad”: add words, patterns or distinct symbols. If a connector arrow carries meaning, state that meaning in the text. A left-to-right arrow should not be the only way to understand the order.

Use this copy worksheet before designing

  1. Reader question: Write the exact question in one sentence.
  2. Outcome: Name one task the reader can perform afterward.
  3. Core relationship: Sequence, comparison, category or component diagram?
  4. Visible title: Promise the lesson, not a guaranteed result.
  5. Labels: Draft three to five short, distinct labels.
  6. Text equivalent: Explain the full idea in two or three paragraphs before creating the image.
  7. Alt text: Summarize the image's informational role without keyword repetition.
  8. Source notes: Record where factual claims or numerical values came from.
  9. Small-screen test: Check the actual published size and zoom behavior.

Review claims and examples before publishing

Imagine your infographic shows “100 clicks → 80 visits → 8 signups.” If those numbers are fictional, label them “illustrative example, not actual campaign performance.” Explain that analytics tools may measure different events, filters and reporting windows. The example illustrates a distinction; it is not evidence of a typical conversion rate.

For a tool comparison, do not put a provider's logo beside an invented performance score. Verify feature descriptions against current documentation and note the date checked. For an earnings-related visual, remove unsupported income figures rather than decorating them with small disclaimers. A claim that cannot be supported in the article should not appear in the image.

Publish the graphic as one part of a useful page

Give the page a descriptive title, a direct introductory answer, and headings that follow the task. Include the diagram near the step it clarifies. Use descriptive file names for asset management, but do not mistake a filename for meaningful alt text. If the image is linked, ensure the link has an understandable accessible name.

Check the page with images disabled or unavailable: can a reader still complete the task? Navigate using a keyboard, enlarge the page on a phone, and confirm that reading order remains sensible. If the text equivalent does not teach the process independently, improve it before publishing.

When an infographic is the wrong choice

If the lesson needs several conditional decisions, a short tutorial with headings may be clearer than a crowded poster. If the information changes frequently, a maintained HTML table or checklist may be easier to correct than a static image shared across many accounts. The goal is understanding, not a larger asset inventory.

After publication, keep a source file and revision note. When the underlying article changes, update the visual and its text alternative together. Otherwise, an old graphic can quietly contradict the current instructions.
