Technical SEO Checklist for a Small Static Website

Technical SEO helps search engines discover the pages that already deserve to be found. It cannot make thin content useful or guarantee inclusion in search results.

Written as a practical educational resource. It is not a guarantee of traffic, customers or income.

Check discoverability first

Open each public page without logging in and verify that useful text is in the HTML response. Give every page an accurate title, meta description, main heading, and clean internal link. Avoid blocking important pages in robots.txt. A page excluded by a robots directive may not be crawled as intended; use a page-level noindex when a public utility page should not appear in search.

Use the right canonical host

When a website has multiple accessible hostnames, choose one publicly preferred URL for each page. Add an absolute rel=canonical tag using the final live domain, not a guessed temporary preview hostname. This repository intentionally leaves canonicals and sitemap absolute URLs unset until the Wasmer production host is verified.

Write accurate structured data

JSON-LD can explain the page type, publisher, and article date to search systems, but schema fields must match visible content. Do not invent review stars, prices, ratings, authors, or real-world credentials. Test structured data with Google's available tools and treat eligibility for enhanced presentation as conditional, not guaranteed.

Prioritize page experience and maintenance

Serve HTTPS, size media sensibly, avoid intrusive full-screen prompts, keep controls keyboard accessible, and use descriptive anchor text. Check for broken links and redirect chains. Review pages after publishing, because a perfect sitemap with broken content does not help the visitor.

Try this exercise

Open three pages on a phone and read only their title, first heading, and first paragraph. Can you tell how they differ? Then confirm navigation works with the keyboard and no popups hide the content.
